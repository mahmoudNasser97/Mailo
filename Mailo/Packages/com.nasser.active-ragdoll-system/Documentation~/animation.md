# Animation

Everything here is generated by **Tools → Nasser Active Ragdoll System → Character Setup**.
You assign clips to a `LocomotionClipSet` asset; the wizard builds the graph.

---

## The clips to download

All of these exist free on Mixamo. Search terms in the right column.

### Required — nothing works without these

| Slot | Mixamo search | Notes |
|---|---|---|
| Idle | `Breathing Idle` | Must loop. Avoid clips with big weight shifts. |
| Walk Forward | `Walking` | In place = OFF. The root motion is measured. |
| Get up (face down) | `Stand Up` | Prone → standing. Not looping. |
| Get up (face up) | `Getting Up` | Supine → standing. Not looping. |

### Strongly recommended — this is where "smooth" comes from

| Slot | Mixamo search |
|---|---|
| Walk Backward | `Walking Backwards` |
| Walk Left | `Left Strafe Walking` |
| Walk Right | `Right Strafe Walking` |
| Run Forward | `Running` |
| Run Backward | `Running Backward` |
| Run Left | `Left Strafe` |
| Run Right | `Right Strafe` |

Without the strafe clips, walking sideways plays the forward walk while the body
slides diagonally. It reads as broken even to people who can't say why.

### Optional polish

| Slot | Mixamo search |
|---|---|
| Jump Start | `Jumping Up` |
| Fall Loop | `Falling Idle` |
| Land | `Hard Landing` |
| Carry Pose | `Standing Idle` (holding) — any two-handed carry pose |
| Reach Pose | `Reaching` |

Download all of them onto **one** character so the skeletons match, then use
**Rig → Animation Type → Humanoid** on every FBX.

## The graph the wizard builds

```
Base Layer
  Locomotion              1D blend on Speed
    ├ Idle                threshold 0
    ├ Walk                2D Freeform Directional on MoveX / MoveY
    └ Run                 2D Freeform Directional on MoveX / MoveY
  JumpStart → Fall → Land driven by Grounded
  GetUpProne              played by name, exits on exit time
  GetUpSupine             played by name, exits on exit time

UpperBody Layer           AvatarMask: both arms + fingers + chest
  Empty ↔ Carry           driven by Carrying
```

**Why nested rather than one flat 2D tree.** A flat tree containing walk and run
clips has to interpolate between gaits with different contact timings. The
result is the floaty half-step everyone recognises as "blend tree locomotion".
Splitting speed (1D) from direction (2D) means every 2D blend happens between
clips that share a gait, and the only cross-gait blend is a single 1D one along
a parameter that changes slowly.

---

## The three things that actually make it smooth

Most people build the graph correctly and still get twitchy results, because
smoothness is mostly runtime, not graph topology.

**1. Facing-relative direction.** `MoveX`/`MoveY` are computed from velocity
transformed into the controller's local space, not world space. Without this,
turning while walking swings `MoveX` from −1 to +1 and the strafe blend thrashes
even though the character is doing something simple. `CharacterBody.DriveAnimator()`.

**2. Damped parameters.** Every `SetFloat` uses the damping overload
(`speedDamping` 0.12s, `directionDamping` 0.08s). Physics velocity is noisy
frame to frame — a rigidbody standing still still jitters by a few cm/s — and
undamped that noise goes straight into the blend weights.

**3. Playback rate synced to real speed.** `syncPlaybackToSpeed` scales
`Animator.speed` so the feet travel as far as the body does. If the threshold
says 1.6 m/s but the clip actually moves 1.1 m/s, the feet skate by 45% and no
amount of damping hides it. Damping conceals twitching; only this fixes sliding.

Two supporting details the wizard also handles:

- **Auto thresholds.** Blend thresholds are read from each clip's own
  `averageSpeed` rather than guessed. This is why *Fix clip import settings*
  leaves `lockRootPositionXZ = false` — baking XZ into the pose makes
  `averageSpeed` read zero and the measurement silently falls back to guesses.
- **`AnimatorUpdateMode.AnimatePhysics` on the puppet.** The muscles read the
  puppet pose in `FixedUpdate`. On the default `Normal` mode that pose is stale
  on some physics steps and fresh on others, producing a subtle high-frequency
  judder that is very hard to diagnose after the fact.

## Import settings

The **Fix clip import settings** button applies these to every locomotion clip:

| Setting | Value | Why |
|---|---|---|
| Loop Time | on | Obvious, still forgotten constantly. |
| Root Transform Rotation → Bake Into Pose | on | Facing is ours, not the clip's. |
| Root Transform Position (Y) → Bake Into Pose | on | Vertical bob comes from the ride spring. |
| Root Transform Position (XZ) → Bake Into Pose | **off** | Needed to measure clip speed. |
| Based Upon | Original | Keeps Mixamo's authored orientation. |

Note the asymmetry on the last two — Y baked, XZ not. That combination is
correct here and unusual enough to be worth remembering.

## Troubleshooting

**Feet slide.** Check the Console for the "no measurable root motion" warning. If
present, XZ is baked into pose — run the fix button. If absent, tune
`referenceClipSpeed` on `CharacterBody`; the wizard sets it from the walk clip
but a mismatched run clip can still skate.

**Blend flickers between walk and run.** Your two thresholds are too close. The
builder forces at least 1.2 m/s of separation, but if you set them by hand,
don't.

**Character T-poses for a frame on recovery.** A get-up clip is missing, so the
state is empty. Assign it, or the graph plays nothing for that state's duration.

**Upper body snaps when picking things up.** Increase the Carry transition
duration in the generated controller (default 0.25s). It's a normal transition —
edit it like any other.

**Everything is smooth but feels laggy.** Lower `speedDamping`. There is a real
trade here: damping buys smoothness with responsiveness, and 0.12s is tuned for
a heavy, physical character. For something nimbler try 0.06.

**Arms don't follow the animation at all.** Expected for players — the hands are
physics bodies dragged to camera-space targets, so the upper-body layer mostly
affects shoulders and elbows. NPCs show it more, since their targets are
chest-parented.
